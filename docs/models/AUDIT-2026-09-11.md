### A defect found and fixed during verification

The first run of the new incremental loader failed with
`400 Bad Request … start=1789057441076.0`. The catch-up computes `days` as a
**fraction** of a day from the last stored row, and `load_liquidations` built
`start_ms = now_ms - days * DAY_MS` — a float, which the archive API rejects.
Fixed by flooring the boundary to whole milliseconds
(`start_ms = int(now_ms - float(days) * DAY_MS)`); the next run returned
`status=ok`. Recorded under D-104.
