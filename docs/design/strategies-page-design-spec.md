# Strategies Pages: Design Spec for Perpl Terminal

Companion to `strategies-page-mockup.html` (open it in a browser; buttons bottom-right switch Overview / Strategy detail and light / dark). This spec is written to be handed to Claude Code together with the mockup.

## 1. Design principles

- Same visual language as the Analytics page: same nav, Inter, white or dark surfaces, blue accent, 13 to 14px table text, one-line row rhythm, pills for state. Nothing new in the look. The Strategies pages should feel like a sibling of Analytics, not a different product.
- One new element carries the page: the **conditions panel**. It shows, for one strategy, every rule from the strategy doc as a live checklist with pass / fail / waiting and the actual measured value next to the threshold. This is what turns the page from a stats dump into a review tool. Everything else stays quiet.
- Every number that appears in the strategy docs (thresholds, targets, kill levels) appears in the UI next to its live value, so a rule change in the doc is visible in the product.
- Plain sentence-case copy. "Waiting for" not "Status detail". "Fired long" not "SIGNAL_LONG".
- Paper and live results are never mixed in one number. Paper numbers get a small "paper" tag.

## 2. Navigation

Add **Strategies** under Trading, between Copy trade and Terminal (nav order: Copy trade, Strategies, Terminal). Uses the same active style as Analytics. Routes:
- `/strategies` overview
- `/strategies/:id` detail, where id is `01` to `06`

## 3. Page A: Strategies overview (`/strategies`)

Layout top to bottom, same 40px page padding and max width as Analytics.

**Header row.** Title "Strategies", one-line subtitle, right side: global mode segmented control (Paper | Live) and a "venue · last update" line. Global mode is the master switch; a strategy cannot be Live if global is Paper.

**Risk engine strip.** One bordered row of six cells (equity; today's P/L against 4% daily cap with a progress bar that turns amber past 50% and red past 80%; open positions n of 2; risk per trade in % and dollars with max leverage; consecutive losses with pause threshold; fees this month as dollars and % of gross). This strip is the shared risk engine made visible. Same on every strategies page.

**Strategies table.** One row per strategy, sorted by evidence rank (05, 01, 04, 03, 02, 06) by default, sortable by any numeric column. Columns:
1. `#` strategy id
2. Strategy name, with a one-line grey subline (assets or scope)
3. Status pill: Live (green), Paper (amber), Timing only (grey, used by 06), Off (grey), Paused (red, from kill switch or daily cap)
4. Waiting for: one sentence, generated by the strategy, describing the next thing it needs (this is the "state machine in words")
5. Setups today
6. Trades 30d
7. Win rate
8. Profit factor with a small inline bar (bar full at 2.0)
9. Net P/L 30d, green or red
10. Enable toggle (per strategy)

Row click opens the detail page.

**Open positions table.** Strategy, asset, side pill, size and leverage, entry, stop, targets, unrealised, "exit at" sentence.

**Recent signals table.** Last 24h, fired and skipped together. Columns: time, strategy, asset, result pill (Fired long / Fired short / Skipped / Not confirmed / Not filled), reason sentence naming the failing condition with the value, score. Skipped signals are as important as fired ones; do not hide them.

## 4. Page B: Strategy detail (`/strategies/:id`)

Same template for all six; content and the conditions panel vary.

**Breadcrumb** "Strategies / 05 Session open momentum".

**Header.** Name with status pill, one-line description with venue, assets, risk and leverage. Right side: per-strategy mode segmented control (Off | Paper | Live), "Parameters" button (opens drawer), "Backtest" button (opens last backtest report and a run button).

**Stats strip.** Six cells for the last 30 days: trades; win rate with target range from the doc; profit factor with kill level and bar; expectancy per trade; max drawdown ($ and %); fee drag (% of gross). Toggle 7d / 30d / 90d / all.

**Main grid.** Left: chart card. Right: conditions card, 360px wide. On narrow screens the conditions card stacks above the chart.

**Chart card.** 15m candles for the selected asset (asset segmented control in the card header), reusing the existing Terminal chart component. Overlays are strategy-specific (section 5). Always drawn: entries (green circle), exits (small square, green or red), stop line (red dashed), target lines (green dashed), and a grey wash over time ranges where the strategy is not allowed to trade (outside session window, gate closed, macro block). Legend under the chart.

**Conditions card.** Three stacked parts:
1. State header: "Current state" label with the state value in words (Waiting for range, Range set, Break seen, Armed, In position, Done for session, Gate closed) and a pill on the right (Filled 13:33, or Skipped, or Waiting).
2. Conditions list: one row per rule in the strategy doc. Left icon green check / red cross / grey dot (not evaluated yet). Middle: rule name in one short phrase, with a small grey subline saying what it measures. Right: the live value and the threshold in the form "82nd pct (need 60)". Rules are listed in the order the strategy evaluates them.
3. Score block: one row per score component with a bar and its weighted value, then a total line "Score 0.72, fires at 0.65" with a Fired / Below threshold pill. Under it a 2x2 key-value grid: entry, size and leverage, stop with dollar risk, targets.

**Tabs under the grid.** Signals (default, same columns as overview but with a session or trigger column per strategy, plus outcome), Trades (full trade log with MAE and MFE), a strategy-specific breakdown tab (section 5), Parameters, Changelog.

**Parameters drawer.** Every parameter from the strategy doc as a labelled input with its default and unit. Saving requires a one-line reason; the reason and the diff are written to the Changelog tab. Live strategies show a confirm step before saving.

## 5. Per-strategy variations

Only the chart overlays, the conditions list, the "waiting for" sentence and the breakdown tab change. The template does not.

### 01 Liquidation sweep reversal
- Overlays: liquidation fills as small red (long liqs) or green (short liqs) ticks under the candles sized by notional; the liquidation map as a horizontal heat strip on the right edge of the chart (0.25% bands, intensity by notional, number of wallets on hover); the cascade window shaded; the wick extreme and the 50% / 70% retracement lines.
- Conditions: cascade notional in 5 min vs minimum; distinct wallets vs 25; move vs 1.2 ATR; quiet time vs 45 s; taker volume vs 40% of peak; depth refill vs 60%; next cluster within 1 ATR vs 50% of swept; regime; funding leaned crowd side; CEX cascade confirmed; timing.
- Waiting for: "Cascade of $3M in 5 min, largest so far $1.1M" or "Cascade seen, quiet for 21 of 45 s".
- Breakdown tab: by asset, by cascade size bucket, by quiet-time; MFE before fill distribution.

### 02 Funding settlement flow
- Overlays: vertical lines at 00:00 / 08:00 / 16:00 UTC, the T-30 to T+30 window shaded, a small funding sub-pane under the candles showing HL hourly (x8) and Binance 8h with the EXTREME band shaded.
- Conditions: crowding level vs EXTREME; OI 24h change vs 3%; adverse move in prior 2h vs 1 ATR; regime; Binance hourly-cap regime not active; timing.
- Waiting for: "Next window 16:00 UTC, funding normal (z 0.6)".
- Breakdown tab: by settlement time, by crowding source (z-score vs absolute); plus the gauge report: other strategies' expectancy with vs against the funding tilt.

### 03 Whale following
- Overlays: cohort opens and adds as small markers with wallet count on hover; cohort VWAP entry line; the entry zone (VWAP -0.5 ATR to +0.2 ATR) shaded.
- Conditions: fresh wallets same direction vs 3; net direction vs 0.3; price within 0.5 ATR of cohort VWAP; not more than 1 ATR adverse; regime; timing.
- Waiting for: "1 cohort wallet long ETH in the last 60 min, need 3".
- Breakdown tab: by cohort wallet (which wallets generated winning events), lag from first cohort open to our fill, cohort forward P/L per rebuild. A "Cohort" side tab lists the 30 wallets with score, since date and metrics, and links to the existing trader profile.

### 04 Volatility compression breakout
- Overlays: the compression box; the break candle highlighted; OI as a thin sub-pane under the candles with the box-start OI level marked; depth-beyond-box as a small badge.
- Conditions: bbw rank vs 20%; ATR rank vs 25%; compression candles vs 8; break distance vs 0.15 ATR; break range vs 1.5x mean ATR; OI change since box vs 1.5%; OI during break not below -0.5%; 1h Hull agrees; 4h Hull not strongly against; depth beyond box vs 80%; realised vol rising; regime.
- Waiting for: "ETH compressing 9 candles, box 2,214 to 2,231" or "Break seen, waiting for retest, 2 of 3 candles".
- Breakdown tab: back-inside rate, OI change on winning vs losing breaks, time of day of winners.

### 05 Session open momentum
- Overlays: opening range box; session trade window; grey wash outside the window.
- Conditions: as in the mockup.
- Waiting for: "US open in 42 min, vol-day yes (82nd pct)" or "EU session skipped, low-vol day".
- Breakdown tab: by session (EU, US, Monday Asia) and by realised-vol percentile bucket.

### 06 Hull + Fisher + EMA pullback
- Overlays: EMA 200, Hull 55 coloured by slope, Fisher as a sub-pane with the -1.5 / +1.5 lines and signal line; pullback candles shaded.
- Conditions: shared regime; OI direction matches price over 4h with 1% minimum; funding not extreme; realised vol above 24h average; no macro within 2h; 12 consecutive closes beyond EMA; distance from EMA between 0.5 and 3 ATR; pullback 2 to 8 candles reaching Hull zone; Fisher extreme then cross; Hull still up; 1h Hull up; bias not against; stop within 1.2 ATR.
- Waiting for: "Gate closed: BTC OI falling while price rising".
- Breakdown tab: gated vs ungated side by side (trades, win rate, PF, drawdown) with the PF gap highlighted; timing-layer audit (other strategies' expectancy with timing score above vs below 0.6). This strategy also shows a "Timing layer" pill in the header because strategies 01 to 05 depend on it.

## 6. States, empty states, errors

- Strategy never run: conditions card shows all grey dots and "Waiting for first evaluation". Stats strip shows dashes, not zeros.
- Data feed stale (last update older than 60 s): amber banner at the top of the page "Hyperliquid feed is 3 min behind. Strategies are paused until it catches up." Same wording on both pages.
- Kill switch tripped: status pill "Paused", red banner on the detail page with the reason ("Profit factor 0.84 over the last 20 trades, below 0.9. Review and re-enable from Parameters.") and a "Re-enable" button that requires a reason.
- Daily cap hit: global mode flips to Paper, strip cell turns red, banner "Daily loss cap reached (4%). Live trading resumes at 00:00 UTC."

## 7. Alerts

Telegram alerts already exist in Settings. Add per-strategy checkboxes there: fire, skip, pre-alert, kill switch, daily cap. Alert text format is defined in each strategy doc (section "Signals and notifications"). Every alert links to `/strategies/:id`.
