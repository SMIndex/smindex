# Models M1–M6 — implementation decisions (ambiguities resolved from the code, not assumed)

Each entry: what the docs (10–17) left open, what the code does, why. Nothing here changes a
documented threshold; where a doc value looked odd it was kept verbatim and noted.

| # | Decision |
|---|----------|
| D-01 | **Parallel registries for models.** `seed.MODELS` / `seed.MODEL_PARAMETERS`, `conditions.MODEL_CONDITIONS`, `mode.MODEL_IMPLEMENTED`, `model_runner.MODEL_REGISTRY`. The 01–06 registries (`evaluator.REGISTRY`, `seed.STRATEGIES`, `backtest.runner.REQUIRED`) have exact-set unit tests and doc 17 forbids changing 01–06 behaviour, so the models are registered beside them, never inside. `router._NAMES = dict(STRATEGIES + MODELS)` so the API resolves both. |
| D-02 | **`AND model IS NULL` in `PaperTradeManager.manage`** pending/open queries. Model trades are lifecycle-managed by `ModelTradeManager` (partials, BE, trail, thesis exits) — the 01–06 manager must not also resolve them. 01–06 rows have `model IS NULL`, so their behaviour is unchanged. |
| D-03 | **Daily candles are aggregated from 4h.** `strat_candles` stores 15m/1h/4h only; no daily feed exists and none is invented. A UTC day is emitted only when all six 4h candles exist; its ts = close ts of the day's last 4h candle (same close-time semantics as stored tfs). |
| D-04 | **`displacement_grade` formula kept verbatim** from doc 10 §2.3: `min(1, (range/1.5ATR) × (body/0.6)) / 2`. It caps at 0.5, so reasons that read the grade never exceed 0.5 strength from this component alone. Not "fixed" — the doc is authoritative. |
| D-05 | **Paper fills are modelled on the `strat_book_5s` mid tape** with the existing strict `limit_fills_through` (a resting post-only order fills only when a later mid trades THROUGH it). Stops trigger on mid via `stop_triggered` and pay taker; T1/T2/trail exits pay maker (`compute_close`). Conservative by construction; no fill is assumed at touch. |
| D-06 | **Migration v15 is a shared function** (`app/db/migrations_models.apply_v15`) run by BOTH the API lifespan and the worker start, guarded (`INFORMATION_SCHEMA` checks) so whichever process boots first applies it and the other is a no-op. |
| D-07 | **`mind_model_state` table** (model, coin, key → JSON) holds frozen Asia range (07:00), weekly levels (Monday 00:00), 07:00/14:00 day-type labels, per-day/per-week attempt counters and flags. Frozen values survive worker restarts; nothing is recomputed from a later window. |
| D-08 | **`strat_alert_prefs` table + `GET/PUT /api/strategies/alerts/prefs` endpoints** back the per-model Settings checkboxes. Absent row = enabled. The outbox drain filters per recipient wallet by model. |
| D-09 | **Every closed 15m each model writes one `strat_signals` row per coin even with no setup.** Doc 17 7b requires ≥1 signal row per model in 30 min and 7c requires Mind fields on every evaluation. Without a setup the setup-dependent detectors read 0 and a synthetic veto `no_setup: <what is missing>` is attached via `snap.extra_vetoes`, so raw/conviction/reasons/vetoes/multipliers/thesis are populated and the row is honestly a non-trade. |
| D-10 | **`strat_trades.lifecycle_json`** holds the per-trade state machine: phase (pending/open/partial), entry_valid_until, t1/t2/t3, t1_done, be_done, trail_ref, hard_stop_ts, initial_risk_dollars, fail_streak, partial_pnl, remaining_size, and the setup facts the in-trade checks need (level, wick, OB bottom, entry-time OI/cohort). `in_trade_checks_json` is the append-only log of each 15m Mind.manage result. |
| D-11 | **Trailing simplified to a stated rule:** once a model's trail condition is met (per its doc), on each closed 15m the stop moves to the last confirmed 15m swing low (higher low) if above the current stop — mirror for shorts. M4/M6 use 1h/4h swings as their docs say. |
| D-12 | **`r_multiple = pnl_net / initial_risk_dollars`**, `initial_risk_dollars = size × |entry − initial stop|`. Partials are summed into pnl_net first; BE/trail moves do not change the denominator. |
| D-13 | **Weight history = `strat_changelog` rows with `wallet='mind-learn'`** (`strategy_id=<model>`, `diff={week, changes:[{reason, from, to, diff_r, n_strong, n_weak}]}`). Proposed-but-not-applied changes (learning disabled / first 60 days) are logged with `wallet='mind-learn:proposed'`. Flags (`review`, `mind_not_discriminating`) live in `mind_model_state` under `coin='*'`, key `flag:<name>`. |
| D-14 | **Pending/open resolution runs every scheduler tick** (book mids arrive every 5s); `Mind.manage` runs once per closed 15m per open position. Entry-validity expiry cancels on the tick that passes `entry_valid_until`. |
| D-15 | **Cohort = the existing smart-money cohort** (`cohort.cohort_signal`) as the 01–06 strategies use it. "Cohort Δ24h" = `net_dir` now − `net_dir` at the latest analytics cycle ≤ 24h ago. "Cohort adding" = OPEN/INCREASE/FLIP flow events in the last 60 min on that side. |
| D-16 | **Liquidation clusters** come from `analytics_positions` (latest cycle) liq prices in 0.25% bands of mid, qualifying at ≥0.1% of coin OI (`strat_oi_1m.oi_notional`). `liq_cluster_long` = longs that liquidate BELOW price (fuel for a down move); `liq_cluster_short` mirror. Wallet counts are distinct wallets in the band. |
| D-17 | **Realised liquidations** (`strat_liquidations.side`) = side of the LIQUIDATED position (verified against the ingest). "Short liquidations" in a doc = rows with `side='short'`. |
| D-18 | **Funding sign convention** follows `strat_gauge`: positive `funding_z` = crowd long; `crowding_level` EXTREME at |z|≥2; `blocked_direction` = the crowded side. "funding_extreme on the trade's side" = `crowding_level == 'EXTREME' and blocked_direction == direction`. |
| D-19 | **Volume-profile bins** are 0.05% of price; a candle's volume is spread uniformly over the bins its range spans; value area = 70% expanding from POC. Uses the closed 15m candles of the UTC day. |
| D-20 | **Doc thresholds referencing "the entry" for post-only orders**: the limit sits at the documented offset; if the offset is stale when the runner next ticks (price already through), the order is still placed at the documented price and may never fill — we do not chase (doc 17: "model post-only fills conservatively"). |
| D-21 | **Model paper equity / sizing** reuse `GlobalRisk.size_for(entry, stop, equity, risk_pct, max_leverage=3.0)` with `risk_pct` 1.5 (full) / 0.75 (half). RiskEngine limits untouched (doc 17 rule). |
| D-22 | **No live mode for models.** `config/models.yaml` `mode: paper` is the only accepted value; the runner raises on anything else at load. No venue adapter exists and none was built. |
| D-23 | **07:00 / 14:00 day-type labels** are frozen in `mind_model_state` (key `day_type:<YYYY-MM-DD>:07` / `:14`); the running label (recomputed each 15m) is what the alignment table and Minds read between those times, per doc 10 §3 ("running label"). |
| D-24 | **`no_trade` day type** needs `rv_pct` (30-day RV percentile from closes) AND `vol_2h_ratio` (needs ≥5 prior days of same-slot volume). With <5 days of 15m history the inputs are None and the classifier can never say `no_trade` — it says `range`. Not invented. |
| D-25 | **`no_higher_low` semantics** (docs 11/15 in-trade check): with ≥2 closed 15m candles since fill, failing when NO candle since entry has made a low above the sweep wick and then a higher low after it — i.e. the tape has not printed a higher low. Mirror for shorts. Recorded as one failure (counts 1). |
| D-26 | **M1 range reference**: the 4h range, or the 1h range when the 4h range is wider than 6 ATR(4h) — doc 11 says "premium/discount of the current range"; a >6 ATR 4h range is a trend leg, not a range, so the 1h range is what the entry can be located in. |
| D-27 | **M3 failure counters** are per level per UTC day (`failures:<level>` in `mind_model_state`), incremented once per distinct SFP candle at that level (`last_sfp` de-dupes re-evaluations of the same failure — corrected by audit D-45; the original text said "only on a TAKEN trade", which made the doc's "third failure" multiplier unreachable); the `second_failure` reason and the failures-at-level multiplier read the counter excluding the current SFP. A 4h swing high / equal highs / pwh / pdh / prior-session high are the level types (doc 13 §Levels), with location strengths 1.0 / 1.0 / 1.0 / 0.8 / 0.6. |
| D-28 | **M3 acceptance** = two consecutive 15m closes beyond the level with OI rising across the pair (doc 13 line 46). The pair is searched over every candle after the failure candle including the latest closed one. |
| D-29 | **M4 is evaluated on every closed 15m** (a superset of doc 14's "each closed 1h + each 15m while pending"); the CHoCH must be ≤ 72h old and the 4h leg needs ≥ 5 BOS **or** ≥ 8% 3-day extension before it qualifies as "extended" (wording corrected by the audit — the code has always used OR, matching doc 14 §Sequence "at least 5 consecutive BOS or 8% in 3 days"). |
| D-30 | **M1 second attempt** (doc 11 "if unfilled, rest at the FVG mid"): the FVG-mid order is placed when the first order expires and rests for 6 more candles (one expected hold); it is the bullish/bearish 15m FVG created within one candle before to `candles` after the reclaim; no FVG → no second attempt. |
| D-31 | **Feed-missing vetoes**: the docs' OI / taker / book gates cannot be checked without the feed, so a missing feed is a recorded veto (`feed_missing_oi`, `feed_missing_taker` for the last hour; `feed_missing_book` for the last 5 minutes) — never an assumed pass. Book missing also means no paper fill is possible. |
| D-32 | **M5 window candles** are those CLOSING inside the window (`ts > window_start`; first closes 07:15 / 13:15). Session open = open of that first candle. The Asia range used is `Structure.asia` unless the 07:00 frozen copy exists; hard stop = window end + 120 min; the per-window attempt is recorded only when TAKEN. |
| D-33 | **M3 acceptance surfaced as the veto, not a sequence miss.** A lone close beyond the level after the failure undoes the failure (sequence miss, "no swing-failure + retest"); two consecutive closes beyond with OI rising keep the candidate and the `acceptance` veto is the recorded reason. Same "no trade" outcome; the label is what the doc's test list requires. |
| D-34 | **M4 cohort still with the old trend**: `0 < Δ24h < 0.15` is a sequence miss ("still with the old trend"); `Δ24h ≥ 0.15` falls through so the documented `cohort_adding_longs` veto (doc 14 line 45) is the recorded reason. Doc 14 line 15 (cohort ≤ 0 in the sequence) and line 45 (veto at ≥ 0.15) are both honoured this way. |
| D-35 | **M6**: reclaim window opens Monday 12:00; the "loss" = a 4h close beyond the weekly open Mon–Wed; a 15m close beyond BEFORE the 1h reclaim close disqualifies nothing (it is the loss side); `reprice_at` fallback = if the pullback has not come within 4h, re-price the entry at the current price once; Friday 20:00 UTC hard stop; one attempt per week per direction. `oi_falling` veto at OI Δ4h ≤ 0; `0 < Δ4h < 1%` is a sequence miss. |
| D-36 | **Runner conventions**: `cancel_beyond` (M2 OB bottom) checked on each closed 15m while pending; T1 → stop to breakeven universal; M4 T2 partial then trail to T3; `TRAIL_REPLACES_T2` = {M2, M5} (their docs say trail INSTEAD of a fixed T2); `near_t2` = within 0.5 ATR(15m) of T2; `entry_candle_high` = the fill candle's extreme; `recent_form` is per model across coins; `requested_mode == 'paper'` gate at load. |
| D-37 | **Veto tests that exercise the Mind with the model's own setup keys** (M2 `zone_premium`, M4 `daily_strong_against`): building a synthetic 20-day daily trend / premium-zone tape organically is disproportionate for a veto whose detector is a setup flag the model itself computes; the tests feed the model's real setup dict with the flag set and assert the Mind records that veto. All other veto tests are organic (find_setup computes the flag). |
| D-38 | **JSON coercion of numpy ints** (`jsonable`): `np.int64` → `int` (was stringified before the unit test caught it); NaN/±inf → null. Exit alert formats `r_multiple` as `n/a R` when `initial_risk_dollars` is missing instead of raising. |
| D-39 | **`POST /api/strategies/{model}/backtest` returns 404** ("models M1-M6 run forward in paper only; no replay backtest exists"). The 01–06 replay runner (`evaluator.REGISTRY`) has no model entries and doc 17 asks for forward paper only; the background backtest loop iterates `evaluator.REGISTRY` so models are never replayed. The detail page hides the Backtest button for `M*` ids. |
| D-40 | **Model alert switches live on the Settings page behind wallet connect** (the Telegram card is per wallet; `strat_alert_prefs` keys on wallet). Not linked → the card still renders with the note that messages deliver once Telegram is linked; not connected → the whole Telegram section (existing behaviour) is hidden, so the model card is too. |
| D-41 | **UI reuse (doc 17 step 5)**: the model detail page is `StrategyDetailB` with the condition card swapped for a `MindPanel` (reasons as `.cond` rows with strength bars, vetoes, multipliers, conviction + tier, thesis, entry/stop/T1/T2) and the Breakdown tab swapped for `MindBreakdownTab` (weights, calibration, weight history, R by tier). Evaluation-log and trade tables switch column labels only when a model row is present. Pages for 01–06 render exactly as before (their branches are untouched). Route ids `M1`..`M6`; `EVIDENCE_ORDER` appends models after `06u`. |
